# Telegram Shift Checklist Bot

Це MVP Telegram-бота для фото-чекліста зміни.

Що він робить:

- бариста обирає `Відкриття зміни`, `Фото протягом дня` або `Закриття зміни`
- бот надсилає список фото, які треба зробити
- фото потрібно надсилати по черзі
- ШІ перевіряє:
  - чи це справді потрібна зона
  - чи фото схоже на свіже
  - який короткий статус дати по цій зоні
- після завершення бот надсилає підсумок у службовий чат
- протягом дня бот може сам нагадувати зробити контрольні фото

## Головні файли

- `run.py` - запуск
- `app/bot.py` - логіка бота
- `app/openai_client.py` - перевірка фото через OpenAI
- `config/shift_plan.json` - список обов'язкових фото і часи нагадувань
- `prompts/photo_validation_prompt.md` - інструкція для ШІ
- `.env.example` - приклад налаштувань

## Що можна редагувати без програмування

- `config/shift_plan.json`
- `prompts/photo_validation_prompt.md`
- `.env`

У `config/shift_plan.json` ви можете міняти:

- які фото потрібні на відкриття
- які фото потрібні протягом дня
- які фото потрібні на закриття
- параметри випадкових денних нагадувань після обіду

## Як працює сценарій

1. Бариста тисне кнопку режиму.
2. Бот надсилає список фото.
3. Бот чекає перше фото.
4. Якщо фото не тієї зони, бот просить перезняти.
5. Якщо фото прийнято, бот просить наступне.
6. Після останнього фото бот надсилає підсумок у службовий чат.

## Свіжість фото

Бот перевіряє свіжість фото не ідеально, а практично:

- дивиться час отримання фото в Telegram
- пробує читати EXIF-дату зображення, якщо вона є
- якщо фото схоже на старе, просить зробити нове

Це корисна перевірка, але не 100% захист від усіх старих фото.

## Нагадування протягом дня

У `config/shift_plan.json` є:

```json
"random_reminders": {
  "enabled": true,
  "count": 3,
  "window_start": "13:00",
  "window_end": "19:00"
}
```

Бот сам обирає випадкові моменти в цьому проміжку і надсилає в чат активного баристи новий чекліст `Фото протягом дня`.

## Запуск

1. Створіть `.env` на основі `.env.example`
2. Заповніть:

```env
TELEGRAM_BOT_TOKEN=...
TELEGRAM_REPORT_CHAT_ID=...
OPENAI_API_KEY=...
OPENAI_MODEL=gpt-4.1-mini
BUSINESS_NAME=...
REPORT_LANGUAGE=uk
TIMEZONE=Europe/Kiev
```

3. Встановіть залежності:

```bash
pip install -r requirements.txt
```

4. Запустіть:

```bash
python run.py
```

## Працювати Без Ноутбука

Найпростіший надійний варіант для цього бота: `Railway`.

Чому це підходить:

- бот працює як постійний Python-процес у хмарі
- ноутбук можна вимикати
- код залишається у звичайних файлах
- після змін у коді достатньо зробити новий деплой

У проєкті вже підготовлено:

- `Dockerfile`
- `.dockerignore`
- `.gitignore`
- `railway.json`

### Як розгорнути на Railway

1. Створіть GitHub-репозиторій для цього проєкту.
2. Завантажте туди файли цього проєкту.
3. У Railway створіть новий `Service` з GitHub-репозиторію.
4. Railway автоматично збере Docker-образ через `Dockerfile`.
5. У Railway додайте змінні середовища:

```env
TELEGRAM_BOT_TOKEN=...
TELEGRAM_REPORT_CHAT_ID=...
OPENAI_API_KEY=...
OPENAI_MODEL=gpt-4.1-mini
BUSINESS_NAME=...
REPORT_LANGUAGE=uk
TIMEZONE=Europe/Kiev
```

6. Запустіть деплой.

Після цього бот буде працювати незалежно від цього ноутбука.

### Як керувати далі

Є 2 прості варіанти:

- ви редагуєте файли тут, а потім завантажуєте зміни в GitHub
- я змінюю код тут у проєкті, а ви робите новий деплой через GitHub / Railway

Тобто керування ботом усе одно лишається через цей проєкт, але сам бот уже живе окремо.
